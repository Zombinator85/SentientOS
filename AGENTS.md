# SentientOS Repository Agent Map

SentientOS prioritizes operator accountability, auditability, and safe shutdown. Privileged actions and consequential effects require attributable evidence.

## Canonical governance

Current agent taxonomy, privilege contracts, federation rules, procedures, and evidence requirements are indexed by [`docs/GOVERNANCE_DOCTRINE.md`](docs/GOVERNANCE_DOCTRINE.md). Changes to agent privilege must cite their authority source and update the canonical ledger. Compatibility invocations of `bless`, `animate`, or `reflect` continue to log to `/logs/privileges/`.

## Operator and authority boundaries

- Preserve local operator authority and fail closed on ambiguous privileged action.
- Do not add provider invocation, provider SDKs, prompt export, network egress, external disclosure, or runtime provider authority unless explicitly requested.
- Do not add direct host actuation without control-plane admission, audit, rollback, panic, and operator authority. Phase 1 host resource work is read-only; never add fan/PWM/thermal writes without explicit authority.
- Federation evidence, receipts, readiness, proposals, metadata-only work, dry runs, sandboxes, and review evidence are not adoption, consent, policy truth, transport, sync, merge, apply, installation, execution, or live-memory mutation authority.
- Do not modify `prompt_assembler.py` unless explicitly asked. Never put try/catch around imports.
- Operate on `.py` and `.bat` files unless the task explicitly authorizes docs, tests, governance, or other surfaces. Do not edit this file except when explicitly authorized.

## Codex hot path

1. Require the prompt's fresh-current SHA and clean initial tree.
2. Bootstrap first. Stop immediately on `blocked`; `BLOCKED_DO_NOT_IMPLEMENT` artifacts are diagnostic only.
3. Implement a complete bounded task. Preserve validation observations as typed evidence: incomplete is not failed, unavailable is not failed, failed is not task-caused, and pre-existing is not task-caused. Prove candidate regression or inherited debt only with comparable immutable-base/candidate evidence, as specified in [`docs/development/causal_validation_ratchet_integration.md`](docs/development/causal_validation_ratchet_integration.md). Repository health remains visible independently from task regression.
4. Run repository-native focused tests with `python -m scripts.run_tests`, targeted mypy, the relevant matrix, docs/prompt checks when applicable, strict audits, and immutability verification. Focused tests or aggregate counts alone are not behavioral proof.
5. Run the two-phase landing finalizer in the same implementation task. Pre-commit normally requires `ready_to_commit`. It may instead return `ready_to_commit_pending_hosted_validation` when every feasible local check passes, no complete evidence establishes a candidate regression, and each deferred lane has a repository-authorized hosted substitute. A paired, comparable base/candidate timeout remains `comparison_incomplete`; it can authorize only the exact candidate commit needed for hosted validation, never a local pass or merge. Unclassified incomplete evidence, a real candidate regression, failed task acceptance, policy blocks, and `unknown_dirty_tree` block commit.
6. For a hosted-deferred candidate, the post-commit finalizer may return `ready_for_hosted_validation` only for the exact sealed commit and tree. This authorizes only publication of that candidate for required hosted validation; it does not authorize PR metadata or merge. Obtain evidence from `.github/workflows/required-quality-gate.yml` bound to that exact SHA and tree, then run post-commit finalization with `--hosted-validation-evidence`. Only green, complete evidence for every required stage can advance to `ready_for_pr_metadata`; the PR metadata guard must then return `pr_metadata_guard_ready`. Missing, stale, failed, skipped, incomplete, or mismatched hosted evidence blocks merge. Hosted failures are observations and require same-environment base/candidate evidence before they can be classified task-caused. Then generate the PR body from canonical artifacts, require `pr_body_binding_ready`, and seal `pr_publication_handoff_ready` for the exact bytes before PR publication. A payload echo is unverified publication.
7. After external publication, only an independently supplied observation that verifies as `hosted_publication_custody_verified_exact` closes hosted publication custody. A rewritten head is a custody break even when its tree is equal; missing observation remains unverified and must not block truthful pre-publication readiness.
8. Never final-report partial sealing while feasible task-owned repair remains. If no repository change was made, do not commit or call `make_pr`.

The policy source is [`docs/development/codex_validation_and_landing_contract.md`](docs/development/codex_validation_and_landing_contract.md). The executable commands and finalizer statuses are canonical in [`docs/development/codex_finalize_landing.md`](docs/development/codex_finalize_landing.md). Do not copy their full ritual into templates, roadmaps, or prompts.

## Validation commands

Use the canonical command reference above for landing. Core contribution checks are:

- `python -m mypy scripts/ sentientos/` (or task-targeted scope where required; never modify the baseline to hide failures)
- `python -m scripts.run_tests -q`
- `python verify_audits.py --strict`
- `python scripts/audit_immutability_verifier.py`

Behavior-adding tasks must supply the versioned exact-node acceptance manifest described by the validation contract and must name at least one successful-path pytest node. Legacy tasks may omit it only under the documented migration rule.
