# Local runtime provisioning planning

`sentientos.local_runtime_catalog:v1` is curator-supplied metadata for exact Python wheel artifacts used by the active Python `llama_cpp` integration. Each entry binds a stable runtime id, `llama_cpp` engine, CPU/CUDA/ROCm/Metal backend, exact package version, filename, SHA-256, explicit HTTPS artifact URLs, priority, OS, normalized architecture, Python implementation, and exact ABI. Optional size, accelerator vendor, and external prerequisite codes are metadata. Floating versions, latest/search/index URLs, malformed hashes, ambiguous vendors, and empty catalogs fail closed. Catalog input order is normalized by runtime id; matching entries rank by ascending priority and then runtime id.

The immutable `LocalRuntimeEnvironmentProfile` records bounded facts from the current Python process: OS, architecture, implementation, version, ABI, source identity/digest, and missing-fact codes. It is separate from the hardware profile. Observation uses only standard-library process facts and does not probe accelerators, package tools, or networks.

A `sentientos.local_runtime_provisioning:v1` plan accepts only a selected v2 route with model/artifact/route identity and an explicit runtime requirement. Exact engine, backend, OS, architecture (`amd64`/`x86_64` and `aarch64`/`arm64` aliases), implementation, and ABI must match. Accelerated selection does not claim that CUDA, ROCm, or Metal is installed. Explicit external prerequisites remain `not_evaluated`; no prerequisites are `not_required`. Catalog, environment, selection, and final plan identities have deterministic SHA-256 digests without timestamps.

There are three distinct states: (1) a route is hardware-compatible, (2) an exact runtime provisioning target is selected, and (3) the runtime is actually installed and commissioned. This planner stops at state 2. It performs no network, download, package installation, subprocess, runtime/model load, commissioning, host mutation, or authority grant.

The unpinned `optional_deps` hint `pip install llama-cpp-python` remains advisory legacy UX, not artifact custody, and is not consumed. `gpu_autosetup.py` URLs/probes/install behavior and `Start-All.ps1`'s historical 0.2.90 pin, latest download, and mutable setup are legacy installer archaeology, not catalog authority. No trusted production runtime entry currently exists (`production_runtime_catalog_ready = false`); tests use synthetic `.invalid` fixtures.

The bounded chain is: hardware observation → model artifact and execution-route selection → runtime provisioning plan → separately authorized runtime acquisition/install → model acquisition/hash verification → exact launch configuration → commissioning → first boot. The next task is curator custody of a real wheel's exact version, filename, SHA-256, stable HTTPS URL, compatibility fields, and prerequisites, followed by a separately governed executor.
