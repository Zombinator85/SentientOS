# Production post-adoption attribution campaign

The production composer is a thin operator layer over the existing post-adoption
evaluation and attribution-campaign owners. `prepare` seals the exact campaign,
ordered evaluation protocols, predecessor baselines, and intended successor
generation/commit/tree before adoption. `doctor`, `status`, `observe-next`,
`interrupt-next`, `finalize`, `report`, and `verify` always require the exact
campaign identity; none select a latest campaign. Reconstruction verifies all
content-addressed predecessor custody after process replacement.

Production posture is derived, not caller-declared. Readiness validates canonical
generation, continuity, resident-adoption, launch-provenance, completed transition
journal, exact repository tree, immutable target-source records, and a currently
available canonical read-only host collector. The host control adapter retains its
source payload digest, timestamp, collector identity, window, independence, and
preregistered law. Missing, stale, synthetic, malformed, dependent, or mismatched
evidence fails closed; it is never replaced with a fixture.

The composer observes adoption but cannot request it. It has no Git, repository
mutation, process replacement, rollback, provider/network, host-actuation, grant,
or authority-widening effect. Ordered trials remain 2--32, no-retry, no-replacement,
and terminal across restart. The report exposes only an epistemic binding candidate,
the existing developmental evidence record, and (when warranted) the existing
proposal-only campaign signal. It does not update an epistemic proposition.

The resulting capability is **production-capable composition**, not **production
evidence collected**. Even a completed campaign establishes at most repeated
controlled association, never randomized or experimental causal identification,
generality, beneficial recursive self-improvement, monotonic improvement,
consciousness, sentience, personhood, or phenomenal continuity.
