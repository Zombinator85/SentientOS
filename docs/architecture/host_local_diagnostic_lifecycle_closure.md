# Host-local diagnostic lifecycle closure

For the complete operator and reviewer path through source admission, confirmed
execution, confirmed exact rollback, and deletion-independent closure, see the
[host-local diagnostic lifecycle reviewer guide](host_local_diagnostic_lifecycle_reviewer_guide.md).

This read-only subsystem packages one deeply validated completed diagnostic execution bundle and its matching deeply validated completed rollback bundle. The caller supplies both final bundle digests and an explicit closure time. The builder revalidates both public bundle formats before writing anything and rejects inconsistent execution, request, historical correlation, artifact, rollback-plan, or lifecycle identities. A supplied correlation is an equality assertion against the historical execution correlation, never a caller-selected alias, and a mismatch is rejected before any staging or publication path is created.

## Packet custody

Packets are built in an isolated temporary parent, in a child whose name is the derived closure ID, below an explicit external output root. Fixed paths `bundles/execution/` and `bundles/rollback/` preserve every source byte. After copying, both nested bundles are deeply revalidated from the copied bytes; exact content and final manifests and the entire staged packet are then validated before the child is atomically renamed. The final destination is deeply validated again before `latest.json` is atomically published. Thus neither a source-copy race nor a partial staged tree can become a published packet or pointer.

`closure_report.json` explains the identities, times, pending-to-complete lifecycle, direct or reconciled rollback posture, historical call counts, zero closure-processing effect calls, exact mutation boundary, sibling preservation, and broader-authority posture. `summary.json`, `receipt.json`, `content_manifest.json`, and `final_manifest.json` bind exact safe recursive membership and bytes. Both manifests require their exact schema, artifact kind, entry keys, sizes, and SHA-256 digests; duplicate, missing, extra, absolute, traversing, directory, malformed, substituted, and symlink entries fail closed. An unpublished staging parent has a separate staging-identity record which is removed with that parent and never enters the final packet format.

Validation recursively invokes the public deep execution and rollback validators, verifies the externally bound nested digests, recomputes every cross-lifecycle relationship, and rejects duplicates, extras, symlinks, unsafe paths, substitutions, and changed bytes. It never consults current authority or the live target, so a packet remains reviewable after the source bundles and target are removed.

## Publication and non-authority boundary

Closure identity is `hldlc-` plus the first 24 hexadecimal characters of SHA-256 over canonical JSON containing exactly `execution_bundle_digest`, `rollback_bundle_digest`, and `closure_time`. Validation obtains the two digests from deeply validated copied bundles, establishes exact closure-time agreement across records, independently derives the ID, and requires it to match the directory, report, summary, receipt, final manifest, latest pointer, and replay result.

A kernel-owned cross-process lock plus atomic rename provides one publication. Earlier thread-level tests exercised contention within one interpreter; independently spawned-process tests now prove distinct PIDs and module state serialize through the same lock. Descriptor lifetime releases kernel custody on normal exit, exception unwinding, and abrupt process death; the persistent lock-file inode is infrastructure, not evidence of a live owner. Lock custody covers stale-staging inspection, staging, copied-bundle and packet validation, final rename and validation, pointer publication, and cleanup.

While holding the lock, a builder reconciles only staging-prefix directories whose exact staging record, real-directory type, root placement, child identity, and symlink-free membership prove task ownership. A symlink, regular file, malformed staging-like directory, or unrelated content makes publication fail closed without recursive deletion. A child killed after staging creation therefore leaves bounded residue which the next lock owner safely removes. A child killed after final packet rename leaves a complete deterministic packet: the next identical request deeply validates its reconstructed closure identity and packet digest, preserves all packet bytes and filesystem identities, and publishes only the missing pointer. This is recovery of publication, never packet rebuilding or rewriting. Existing invalid packets or conflicting pointers remain untouched and fail closed. The pointer binds closure ID and time, correlation, execution, rollback, source request ID and digest, both bundle digests, final lifecycle, and packet digest. `latest-summary` first validates the exact pointer and its digest, then deeply validates the named packet and compares every bound identity. The CLI continues to provide only `build`, `validate`, and deeply validated `latest-summary` commands.

The packet is historical integrity evidence only. Unkeyed digests do not prove authorship or external authenticity. Building, validating, replaying, and summarizing invoke no execution coordinator, transaction orchestrator, rollback coordinator, rollback primitive, provider, network, subprocess, shell, daemon, dashboard, control-plane, or host-mutation surface. No runtime authority scope or capability is registered.
