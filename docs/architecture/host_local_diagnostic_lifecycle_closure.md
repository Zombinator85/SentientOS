# Host-local diagnostic lifecycle closure

For the complete operator and reviewer path through source admission, confirmed
execution, confirmed exact rollback, and deletion-independent closure, see the
[host-local diagnostic lifecycle reviewer guide](host_local_diagnostic_lifecycle_reviewer_guide.md).

This read-only subsystem packages one deeply validated completed diagnostic execution bundle and its matching deeply validated completed rollback bundle. The caller supplies both final bundle digests and an explicit closure time. The builder revalidates both public bundle formats before writing anything and rejects inconsistent execution, request, historical correlation, artifact, rollback-plan, or lifecycle identities. A supplied correlation is an equality assertion against the historical execution correlation, never a caller-selected alias, and a mismatch is rejected before any staging or publication path is created.

## Packet custody

Packets are built in an isolated temporary parent, in a child whose name is the derived closure ID, below an explicit external output root. Fixed paths `bundles/execution/` and `bundles/rollback/` preserve every source byte. After copying, both nested bundles are deeply revalidated from the copied bytes; exact content and final manifests and the entire staged packet are then validated before the child is atomically renamed. The final destination is deeply validated again before `latest.json` is atomically published. Thus neither a source-copy race nor a partial staged tree can become a published packet or pointer.

`closure_report.json` explains the identities, times, pending-to-complete lifecycle, direct or reconciled rollback posture, historical call counts, zero closure-processing effect calls, exact mutation boundary, sibling preservation, and broader-authority posture. `summary.json`, `receipt.json`, `content_manifest.json`, and `final_manifest.json` bind exact safe recursive membership and bytes. Both manifests require their exact schema, artifact kind, entry keys, sizes, and SHA-256 digests; duplicate, missing, extra, absolute, traversing, directory, malformed, substituted, and symlink entries fail closed. An unpublished staging parent has a separate digest-bound staging identity which is descriptor-written with short-write handling to an exclusively created private `.hldlc-staging-identity-` file, flushed, and atomically installed only after complete canonical bytes exist. The staging directory and publication root are then flushed where supported before packet-child creation. Neither identity path enters the final packet format.

Validation recursively invokes the public deep execution and rollback validators, verifies the externally bound nested digests, recomputes every cross-lifecycle relationship, and rejects duplicates, extras, symlinks, unsafe paths, substitutions, and changed bytes. It never consults current authority or the live target, so a packet remains reviewable after the source bundles and target are removed.

## Publication and non-authority boundary

Closure identity is `hldlc-` plus the first 24 hexadecimal characters of SHA-256 over canonical JSON containing exactly `execution_bundle_digest`, `rollback_bundle_digest`, and `closure_time`. Validation obtains the two digests from deeply validated copied bundles, establishes exact closure-time agreement across records, independently derives the ID, and requires it to match the directory, report, summary, receipt, final manifest, latest pointer, and replay result.

A kernel-owned cross-process lock plus atomic rename provides one publication. Earlier thread-level tests exercised contention within one interpreter; independently spawned-process tests now prove distinct PIDs and module state serialize through the same lock. Descriptor lifetime releases kernel custody on normal exit, exception unwinding, and abrupt process death; the persistent lock-file inode is infrastructure, not evidence of a live owner. Lock custody covers stale-staging inspection, staging, copied-bundle and packet validation, final rename and validation, pointer publication, and cleanup.

While holding the lock, a builder opens the publication root with `O_RDONLY`, `O_DIRECTORY`, and `O_NOFOLLOW` where supported, confirms its device/inode directory identity with `fstat`, and retains that descriptor through reconciliation and normal publication. The configured pathname is rebound before terminal validation, immediately before destructive cleanup, and after successful cleanup. The kernel publication lock serializes cooperating builders but cannot prevent an external filesystem rename, replacement, or symlink substitution; a changed root identity therefore blocks without operating through the replacement.

The builder first classifies every staging directory and temporary-identity candidate into an immutable complete custody plan, and deletes nothing if any candidate is unsafe. After the classified boundary it independently reconstructs the entire reserved-prefix plan and compares candidate identities, exact prepared-identity bytes and associations, immediate membership, and nested canonical snapshots; any difference causes zero deletion. Immediately before each candidate or member removal it rebinds identity, bytes, mode, and authorized membership through opened descriptors. A later destructive-phase mismatch stops cleanup and publication before removing the substitute, reports whether zero or bounded earlier verified task-owned objects were removed, and never claims transactional deletion or recreates evidence. Stale reconciliation uses only basename-and-`dir_fd` unlink/rmdir calls and no-follow descriptor recursion, never `shutil.rmtree`. Stable empty reservations use only nonrecursive removal; complete root-, name-, closure-, schema-, and digest-bound prepared identities may remove only themselves and an associated stable empty directory; only canonical identity-proven, symlink-free staging may be removed recursively. Malformed bytes, substitutions, unexpected membership, symlinks, type or identity changes, and unrelated content are preserved and block publication. Death at reservation, identity preparation, canonical publication, or packet construction therefore leaves bounded evidence that the next lock owner can reconcile safely. A child killed after final packet rename leaves a complete deterministic packet: the next identical request deeply validates its reconstructed closure identity and packet digest, preserves the packet root and every descendant including filesystem identities, and publishes only the missing pointer. This is recovery of publication, never packet rebuilding or rewriting. Existing invalid packets or conflicting pointers remain untouched and fail closed. The pointer binds closure ID and time, correlation, execution, rollback, source request ID and digest, both bundle digests, final lifecycle, and packet digest. `latest-summary` first validates the exact pointer and its digest, then deeply validates the named packet and compares every bound identity. The CLI continues to provide only `build`, `validate`, and deeply validated `latest-summary` commands.

The packet is historical integrity evidence only. Unkeyed digests do not prove authorship or external authenticity. Building, validating, replaying, and summarizing invoke no execution coordinator, transaction orchestrator, rollback coordinator, rollback primitive, provider, network, subprocess, shell, daemon, dashboard, control-plane, or host-mutation surface. No runtime authority scope or capability is registered.


## Descriptor-bound publication custody

The configured canonical publication-root string remains the logical identity used in staging records, reports, deterministic closure identity, and caller-visible packet paths. After the kernel lock is acquired, however, the opened root descriptor (opened read-only with directory and no-follow flags where supported), plus identity-bound descriptors beneath it, is the sole mutation authority. Staging reservation uses exclusive descriptor-relative `mkdir`; staging identity installation, packet commit, and `latest.json` commit use descriptor-relative atomic rename. Packet files are created exclusively beneath the opened packet descriptor with no-follow, exclusive regular-file creation and complete short-write handling.

Deep packet validation remains read-only. It uses an internal `/proc/self/fd` alias whose device, inode, and directory type are checked against the packet descriptor before and after validation; the alias is never serialized. Each publication transition also verifies that the logical pathname remains bound to the initially opened root. Replacement therefore blocks precisely without granting the replacement staging, packet, pointer, validation, cleanup, or replay authority. A replacement after packet rename but before pointer rename leaves a complete unpointed packet in the opened root; restoring that root permits the existing missing-pointer recovery path without rewriting the packet.

Execution and rollback source strings remain the logical paths used for records, findings, and caller-visible identity. Copy read authority instead comes from retained `O_RDONLY|O_DIRECTORY|O_NOFOLLOW` source descriptors. The existing public bundle validators are reused through an identity-checked read-only descriptor adapter; before and after validation, planning, each copy, staged validation, publication, and success, the logical path is rebound to the retained root identity. The immutable internal copy plan records role, safe relative and parent paths, basename, type, device, inode, mode, size, nanosecond mtime, exact directory membership, and regular-file digest under depth, path-length, entry-count, and aggregate-byte bounds.

Packet mutation never uses the read-only descriptor adapter. `bundles`, role roots, and nested directories are exclusively created with `mkdir(..., dir_fd=...)` at private `0700`; regular files use no-follow `open(..., dir_fd=..., O_RDWR|O_CREAT|O_EXCL)` at private `0600`. Source members are rebound no-follow before open, copied with bounded descriptor reads and complete short-write loops, and checked again for identity, metadata, size, and digest after the final read. The destination is flushed, rebound to its directory entry, rewound, and independently digested. Source ownership, timestamps, special bits, and broad modes confer no destination metadata authority: this is byte custody only. Symlinks and unsupported objects fail closed, while injected destination entries are neither entered nor removed.

Content and final manifests are constructed from deterministic descriptor traversal rather than pathname recursion. Its custody snapshot contains the packet root and every descendant's relative path, basename, type, device, inode, private mode, size, nanosecond mtime, exact directory membership, and regular-file SHA-256 digest. After staged deep validation, the final publication hook runs; the complete snapshot is rebuilt and compared, the exact packet is deeply validated again with the same packet digest, and only then may the no-replace rename execute. Root inode and mode alone cannot reveal nested substitution, metadata change, byte mutation, or membership injection. Detecting those changes after publication would leave an invalid deterministic destination blocking retry, so terminal custody rejects them before rename and preserves the staging evidence. The installed descriptor tree is snapshotted and deeply validated once more before pointer publication; all three accepted snapshots are identical.

Reconciliation enforces recorded device, inode, type, mode, size, nanosecond mtime, membership, and (for files) exact bytes and digest at the immediate pre-delete boundary. Directories are checked with their original size and mtime before descent. Authorized child deletion necessarily changes directory size and mtime, so the final `rmdir` boundary instead requires the same descriptor/entry identity and exact empty membership rather than incorrectly comparing post-deletion metadata with the pre-descent snapshot.

## Source-bound no-clobber publication

Descriptor-root custody identifies the authorized parents, while prepared-source custody identifies the exact objects allowed to cross a publication boundary. Staging identity and pointer preparation retain an open regular-file descriptor plus basename, parent role, device, inode, type, private mode, size, nanosecond mtime, exact bytes, and SHA-256 digest. Packet construction likewise retains its open directory descriptor. After each final deterministic hook, the source entry is rebound to that retained descriptor and its metadata before commit.

An earlier destination-absence observation is only diagnostic: a check followed by `os.replace` could overwrite a compatible entry injected between those operations. All three commits therefore call libc `renameat2` with descriptor-relative names and `RENAME_NOREPLACE`. Unsupported kernels fail closed; no pathname or check-then-replace fallback exists. Destination conflicts are distinct from source substitutions, and neither the injected destination nor a substituted source is removed. After a successful rename the destination is rebound to the still-open source descriptor, exact file bytes and digest or packet contents are revalidated, and the destination directory is flushed.

Publication cleanup similarly records each child identity and metadata, invokes its regular-file or directory hook, then reopens and completely rebinds the entry before unlink, descent, or final `rmdir`. A substitution preserves that object and unrelated siblings. If packet and pointer commits are already valid, the result explicitly reports committed publication with cleanup blocked rather than claiming publication success or deleting valid published evidence.

## Descriptor-bound validation and latest replay

Caller-supplied packet and publication paths remain logical names for diagnostics, identity checks, and returned results; after no-follow directory open, retained descriptors are the sole read authority. Public validation surrounds semantic validation with complete descriptor-native snapshots containing relative path, basename, type, device, inode, mode, size, nanosecond mtime, directory membership, and regular-file SHA-256. Execution and rollback validators receive only unresolved, identity-checked `/proc/self/fd/<fd>` read adapters, with each nested tree snapshotted and rebound around its authoritative validator. Adapter paths are neither resolved nor serialized.

Latest replay takes a shared lock on the existing `.closure.lock` without creating it. It retains the publication directory, exact `latest.json` regular-file descriptor (identity, type, mode, size, nanosecond mtime, bytes, and digest), and the descriptor-relative packet directory. Pointer size is bounded to 1 MiB, and `closure_id` must be the canonical `hldlc-` plus 24 lowercase hexadecimal basename before any selected-packet lookup. Terminal root, pointer, packet-entry, and full packet-tree rebinding proves one coherent observation rather than several independently successful pathname reads.

External replacement is detected and left untouched. Validation and replay perform no repair, cleanup, pointer publication, packet mutation, execution, rollback, provider access, or network access.
