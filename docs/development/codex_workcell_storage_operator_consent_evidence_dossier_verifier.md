# Codex Workcell Storage Operator Consent Evidence Dossier Verifier

The Codex workcell storage operator consent evidence dossier verifier is a deterministic, metadata-only structural verifier for a supplied consent evidence dossier JSON. It reads the dossier and optional context JSON reports, records raw-byte SHA-256 digests and byte sizes, and emits a verification report about structure, inventory coverage, missing real-world consent gaps, prerequisite preservation, reviewer-hygiene posture, mount alignment, future activation requirements, and non-authority posture.

The consent evidence dossier inventories consent-design evidence. The dossier verifier checks that inventory. Neither artifact is consent. A verified dossier means only that the metadata shape satisfied the verifier's deterministic checks; it does not mean a request was presented, a UI was rendered, a message was sent, a response artifact was created, an operator response exists, runtime authority was bound, or active storage is allowed.

The verifier checks that metadata-only and dossier-only flags remain true, active authority signals remain false, all supported consent ladder roles are represented, supplied inventory records carry digests and byte sizes, omitted records remain marked missing, verifier statuses match expected values where applicable, consent-design evidence completeness is derived without treating gaps as consent, required blocking gap IDs remain visible, prerequisite IDs are preserved, future activation requirements are inactive, and non-authority posture flags are present and true.

Complete consent-design evidence is still not real-world consent. Request packets, response schemas, finalizer status, PR metadata guard status, daemon recommendations, federation state, supplied evidence, and verifier success cannot create consent, readiness, storage activation, ledger authority, glow archive authority, daemon authority, or runtime binding. Active storage remains blocked until a future explicit consent request presentation mechanism, operator response artifact creation, operator response collection, identity/signature/timestamp/scope/status capture, explicit ledger and glow allows, digest acknowledgements, expiration/revocation acknowledgements, active writer implementations, runtime bindings, tests, and active-behavior docs exist.

Reviewer URL hygiene is reported as documentation hygiene only. Repository grep validation is performed by the landing task, not by this metadata verifier, and it has no runtime effect.

Mount alignment is explicit: `/ledger` is verification-only with no ledger write, `/glow` is verification-only with no archive write, `/vow` is canonical digest context for future consent evidence, `/pulse` is a future watcher boundary that is not activated, and `/daemon` is a future action boundary that is not activated.

This verifier is not a writer, archiver, daemon action, scheduler, consent collector, response collector, UI renderer, message sender, external delivery system, runtime binder, watcher, poller, command runner, readiness authority, commit authority, PR authority, model trainer, reinforcement learner, or federation consensus system.
