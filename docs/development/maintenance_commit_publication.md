# Maintenance commit publication custody

Marker: 9b69d98.

This external maintenance landing controller consumes only `validation_ready_for_commit`. Validation authority remains separate from `repository_commit`, `remote_repository_read`, `remote_ref_publish`, and `pull_request_publish`; none implies force-push, tag/release publication, merge, hosted-check waiting, credential inspection, runtime adoption, or unrelated host actuation. The operator's standing grant remains the publication authority, and no fresh routine confirmation is required for an already admitted landing-capable task.

The closed `sentientos.maintenance_landing_terms:v1` terms bound by grant and narrowed by task lease define repository identity, publication mode (`fast_forward_base_ref` or `pull_request`), remote name, exact base ref, head-ref prefix or exact head ref, commit-title prefix/title, commit identity reference, attempt ceiling, and expiry. Unknown modes fail closed. The commit/PR title is canonical-whitespace normalized and byte-limited; PR head refs are derived as `sentientos/maintenance/<task-id>` and validated with Git ref rules.

The closed `sentientos.maintenance_landing_policy:v1` configuration binds repository roots, external state root, exact Git executable, optional executable digests, optional PR client executable, identity fields, environment-name allowlist, time/output/body ceilings, attempt ceilings, remote-read posture, and constraints. Policy is configuration, not authority.

The immutable `sentientos.maintenance_commit_plan:v1` binds the latest passing validation result, implementation/session/thread identifiers, validation history, worktree descriptor, implementation result, change manifest, patch digest, exact changed paths, validated worktree manifest, base/parent SHA, deterministic title, identity digests, timestamp, Git identity, publication mode/refs, policy digest, and plan digest. Before mutation, the controller verifies journal readiness, active unrevoked lease, landing authority, latest validation, unchanged detached worktree bytes, unchanged patch/paths, detached HEAD at base, no checked-out local branch, and no scope/budget findings; drift returns `commit_workspace_changed` and is not absorbed.

Commit creation uses deterministic Git plumbing with a private external index under the state root: `read-tree`, stage exact validated paths, `write-tree`, and `commit-tree` with exact stdin message. It does not run ordinary `git commit`, hooks, signing, editor, checkout, reset, merge, rebase, tag, branch creation, ref update, or force operation. The detached worktree HEAD and canonical checkout remain unchanged.

The `sentientos.maintenance_commit_result:v1` proves the commit object, single parent, tree equality to the external-index tree and validated worktree bytes, changed paths, modes/blobs, subject, identities, timestamps, no local branch side effect, unchanged detached HEAD, and unchanged canonical checkout. `ready_to_commit_recorded` and `commit_recorded` journal events bind exact validation, plan, result, commit/tree/parent SHA, and commit reference. Exact duplicates are idempotent; conflicting semantic commits fail closed.

After commit recording, the controller renders a bounded UTF-8 publication body and sidecar, then persists `sentientos.maintenance_publication_request:v1` beneath `maintenance_publication_requests/`. Queue truth is a valid immutable request with no terminal successful result, not filename movement. Enqueue performs zero remote operations: no push, remote read, PR client, hosted-status query, or check polling. Local commit success (`commit_ready_publication_queued`) does not depend on remote availability, and publication failure does not invalidate the exact local commit.

A one-shot worker loads one queued request, verifies custody and lease authority, enforces expiry/attempt ceiling, locks per publication, records `publication_started`, publishes exactly according to mode, verifies remote state, persists `sentientos.maintenance_publication_result:v1`, appends `publication_succeeded` or `publication_failed`, and returns without hosted-check polling. Attempt history (`sentientos.maintenance_publication_attempt:v1`) is stable and append-only.

Fast-forward mode reads the exact remote base ref, requires it to equal the commit parent, then pushes only `<commit_sha>:<exact-base-ref>` without force, tags, deletes, mirrors, wildcards, or multi-ref updates. Success means the configured base ref equals the exact commit.

Pull-request mode verifies/reuses or pushes only the exact remote head ref, then uses the configured PR client to list/create/view an exact PR with repository, head, base, title, and body digest. Existing PRs are reused only when all metadata matches. Pull-request creation does not mean merge; auto-merge, reviewers, hosted-check waits, login commands, credential reads, and token persistence are forbidden.

Recovery reuses exact plans, timestamps, commit objects, remote refs, PRs, requests, body bytes, and missing journal events after interruption. If a prior remote effect cannot be distinguished exactly, it returns `publication_integrity_failed`. The future watchdog will discover queued or interrupted work and continue it; this controller does not loop, retry automatically, select candidates, implement, validate, or supervise abandoned tasks.
