# Codex Solo Operating Doctrine

SentientOS is a solo project. The operator is the sole approval and publication authority. The ordinary loop is observe, diagnose, implement, run proportionate local proof, commit, publish, and continue.

GitHub is remote storage, durable history, and a source of asynchronous diagnostics. Hosted checks, review approval, and remote branch protection are not prerequisites for local commit or publication, and remote branch protection is not an active project objective. It remains only an optional future operator choice.

Ordinary landing is governed by exact task acceptance, operator-selected focused regression tests and targeted typing, baseline protection, repository integrity checks, and exact workspace/commit evidence binding. Exhaustive matrix validation is maintenance or release evidence, not per-task ceremony. These workflow rules add no provider, network, host-effect, federation, or runtime authority.

For a context-free local checkout inspection before a task is admitted, use the read-only [Codex fresh-chat orientation](codex_fresh_chat_orientation.md). Its local snapshot supplies context only; it is not bootstrap, hosted-state verification, or implementation, runtime, commit, or publication authority.
