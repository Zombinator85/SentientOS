# Sequence 637 - inject explicit peer Health recovery sources

Sequence 637 gives RuntimeShell an explicit optional dependency for already constructed peer Health recovery sources and passes a defensive mapping copy to FederationPoller. Each source must contain the typed replay owner, a read-only trust catalog, a callable signature verifier, and an integer freshness bound; its owner identity must match a configured peer. Unknown peer keys and mismatched owners fail at initialization. With no source map, behavior remains unchanged and no peer source is inferred from configuration.

This is a composition seam only. It does not load a catalog, attest who provisioned a source, enroll peer identities, add network transport, or connect peer claims to local Health, admission, planning, execution, or decision authority. Any future composition root must supply sources built from operator-controlled exact catalog pins and the governed replay owner; this increment does not claim to prove that provenance. Production peer identity and live telemetry remain unconfigured.
