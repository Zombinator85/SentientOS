# Sequence 640 - reject broad write grants on private Windows custody

Sequence 640 closes a write-side gap in the Windows handle-bound private-file reader. The ACL verifier already rejected untrusted broad read grants, but it did not reject broad write rights. An untrusted local principal could therefore replace a pinned trust-root file or mutate its containing directory even though reads were bound to a safe handle. The verifier now rejects untrusted generic, data, metadata, delete, ownership, and ACL write rights for both files and containing directories. Current user, LocalSystem, and local Administrators remain the allowed principals; unsupported ACE forms still fail closed.

The native Windows regression runs against both the containing directory and file. The Windows Custody workflow now checks out the exact candidate SHA and emits a task-acceptance manifest, verifier result, and provenance bound to those exact test nodes. The new acceptance contract also adds one exact hosted Quality Gate node, taking its required list from 47 to 48.

The first updated hosted gate runs exposed stale hard-coded 47-node checks in pre-commit reconstruction and finalizer validation. Those source-level validators and their contract expectations were corrected before the final candidate. The earlier failed gate attempts are superseded; the final branch and PR gates passed with the corrected exact 48-node list. No acceptance requirement or audit was weakened.
