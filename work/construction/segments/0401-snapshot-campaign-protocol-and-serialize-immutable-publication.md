# Sequence 401: isolate the campaign protocol and serialize immutable publication

The sequence-400 revalidation caught protocol mutation that happened before the call, but a caller sharing the same object could still mutate it between readiness checking and executor invocation. The campaign now retains a separately verified deep protocol snapshot for persisted state and execution. It passes the executor a separate verified copy, and validates that copy before accepting trial evidence. Caller-visible mutation after readiness validation can no longer change the bindings used for the trial; mutation before entry remains rejected.

The campaign's concurrent immutable-readiness test also exposed an intermittent custody error in the shared publisher: after the winning `link()` but before the temporary name was unlinked, a second publisher could see `st_nlink == 2` and misclassify a normal content collision as tampering. `publish_immutable_bytes` now serializes directory publication with a flock on the held private directory descriptor until temporary links are removed and directory durability is handled. It creates no persistent lock artifact and retains first-writer immutable semantics.
