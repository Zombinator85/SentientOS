# Sequence 384: bind readiness receipts to the campaign protocol

The campaign's `run_one()` gate previously trusted only the string `production_trial_ready`. A caller could pass an unbound status mapping or a valid readiness result produced for another immutable protocol. The operation now verifies the readiness schema and digest, checks exact campaign `protocol_id` and `protocol_digest`, preserves the explicit not-ready classification, and requires a ready receipt to contain the complete all-true check set, production evidence posture, no synthetic components, and no authority/effect claim.

Regressions reject a digest-tampered receipt, a correctly formed receipt for a different protocol, a valid negative readiness result, and a status-only mapping before the executor can be called. The existing positive exact-transition path remains covered. The documented readiness digest is an integrity binding; it is not a signature, independent observation, or authority grant. Existing live executor, approval, and custody rails remain necessary.
