# Sequence 394: publish immutable readiness artifacts without replacement races

Production self-reflection readiness artifacts used a read-then-write helper: it accepted an existing path after ordinary JSON comparison and otherwise wrote through atomic replacement. `verify_production_readiness()` can publish outside the campaign lock, so two conflicting concurrent readiness results could replace one another; a symlink to matching JSON could also be accepted as the artifact. The repository already provides descriptor-bound immutable publication for private, bounded artifacts.

The campaign now serializes immutable protocol, receipt, failure, report, and readiness JSON and publishes it through `publish_immutable_bytes`. This rejects symlink and non-private file substitution, preserves identical retries, reports conflicting content as `immutable_artifact_collision`, and applies a 16 MiB bound. Custody errors fail closed as `immutable_artifact_tampered`. Two new regressions prove symlink/collision rejection and concurrent first-writer preservation.
